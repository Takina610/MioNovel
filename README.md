# MioNovel

把散在硬盘上的小说（txt / epub）拖进浏览器，变成一个能离线读、能换主题的书架。

文件不上传，全部存在本机浏览器的 IndexedDB 里，装成 PWA 之后断网也能读。

## 跑起来

```bash
bun install
bun run dev        # http://localhost:5179
```

其它命令：

```bash
bun run build      # 生产构建（含 Service Worker）
bun run preview    # 预览构建产物
bun run typecheck  # tsc --noEmit
bun run samples    # 生成验收用的样例文件到 samples/
bun run verify     # 跑验收（38 项 txt + 45 项 epub + 640 份演示模式文件 + 28 项快捷键 + 161 项办公外壳断言）
bun run verify:decoy   # 只跑演示模式：括号配对、空块、重名方法、行数对齐等
bun run verify:hotkey  # 只跑快捷键：组合解析、键位匹配、录键校验
bun run verify:apps    # 只跑办公外壳：主题 token、块切分、消息/行/幻灯片、云文档首页、Word 开始屏幕与视图页签、章内查找、放真图的形态、界面文案
bun run icons      # 从 public/MioNovel.png 重新生成全套图标（favicon / PWA / apple-touch）
bun run logo       # 从同一张原图派生界面用的小图（logo-64 / logo-192 / favicon.svg）
```

## 用法

拖一个或多个文件到窗口任意位置，或者点「导入」。支持：

- **txt** — 自动识别 UTF-8 / UTF-16 / GB18030（含 GBK、GB2312）/ Big5 / Shift_JIS 等编码；
  分章按中文小说、英文小说、纯数字标题逐级尝试，都不像就按约 3000 字分段。
- **epub** — 读 OPF 元数据、目录（nav.xhtml 和 toc.ncx 都认）、封面；正文里的图片抽出来一起存，
  书自带的样式会被剥掉，排版统一跟主题走。SVG 包 `image` 的整页封面会转成普通 `<img>`；
  中日对照这类双语书（次要语言段落用弱化样式排版）会被自动识别，
  阅读设置里可以切换「对照 / 只看译文 / 只看原文」。

导入之后觉得分章或者编码不对，点书卡片右上角的「⋯」→ 解析设置，改完原地重新解析，
**不需要重新导入**（原始文件一直留着）。epub 没有可调项，但解析器更新之后（脚注、封面、
双语标记这类改进）也能在同一个地方重跑一遍，不用删了重导。

阅读器里：点正文中间显示/隐藏工具栏，翻页模式下点左右两侧翻页、滚轮和触控板也翻页，
窗口够宽时一屏并排两页（放不下就退回单页居中），`←` `→` 翻章，`t` 开目录，
`Esc` 关面板，`f` 全屏。

## 编辑器主题

主题列表里的 **VS Code 暗 / VS Code 亮** 不只是换配色：选中之后整个应用变成编辑器
——书架换成资源管理器（书是文件夹、章是文件），首页不再显示封面，正文按代码排版
（行号、对话与标题的语法配色、右侧缩略图），下面一条状态栏。

打开时是工作区首页，不会自动翻进某本小说：左边是整棵树，点书名或章节才开始读。
点进章节会进阅读器，阅读器的左侧同样是**整个书架**（可以直接换到另一本），
树底下有一行「回书架」。面包屑的第一节也是回首页的出口。读的是正文，
图不渲染——封面、卷首插图、正文插图都会写成一行 `![插图](./OEBPS/Images/pic.png)`，
说明这里原本有一张图、它的原始路径是什么。

编辑器形态下能用的：活动栏切「资源管理器 / 搜索」、点已选中的图标收起侧栏、`t` 开关侧栏、
标签页记录这次会话开过的章、点或拖缩略图跳位置、状态栏上的全书进度与上下章、
本章字数 / 全书字数、`TXT` 编码这类信息都在状态栏右下角。上下章在状态栏常驻，
不用翻到章末才找得到。右侧缩略图写的是**正文本身**（压到 3px 的字），
不是一个占位的色块。

选中这套主题时会顺带把阅读设置调成它自带的一套（等宽、不缩进、段间距 0），
之后就完全按你自己的设置走。颜色是从 VS Code 的 Dark Modern / Light Modern 与
Dark+ / Light+ 的 token 表里抄的，不是照着感觉调的——配套约束见 [docs/SPEC.md](docs/SPEC.md) 五 5.4。

### 演示模式（Alt+Q）

按 `Alt+Q`，或者从标题栏的 ☰ 菜单、阅读设置里的「演示模式」打开，整个窗口换成一份**看着像真的**
源文件：书名变仓库名、章节变文件名、每一段正文变成文件里的一行，状态栏是 `Ln 171, Col 26` /
`TypeScript React` / `Spaces: 2`，浏览器标签页的标题和图标也一起换。再按一次原样回来。

八种语言可选（在阅读设置里）：Java · Spring Boot、C# · ASP.NET Core、Python · Django、
C++ · CMake、React · TypeScript、Vue 3 单文件组件、Go、Rust。每种生成的都是一份**结构完整的文件**：
文件头（package / using / import）、类型声明、若干方法或组件、结尾的收尾行；
文件名和文件里的类名/组件名同源，所以 `CatalogService.java` 里的类就叫 `CatalogService`。
语法高亮交给 highlight.js（按需加载，只在演示模式用），颜色由主题的 token 变量给出。

开关会记住（存在 `mionovel:decoy`），下次打开还在。它不改任何数据，只改显示。

反过来，**只有编辑器形态下才有演示模式**：它在别的主题里该显示什么（飞书是一份假文档、
Word 是一份假 .docx……）还没设计，所以那几套主题下这一栏、这个开关和它的键位都不出现，
`Alt+Q` 也不响应——不摆一个按了没反应的开关。

右侧缩略图跟着一起换——它写的是屏幕上真实显示的那份内容，所以演示模式下也是代码。

### 摸鱼模式（Alt+S）

按 `Alt+S`（或 ☰ 菜单里那一项），左侧文件树和右侧代码区会压暗一层：隔着几步看过去，
屏幕上是一块暗着的编辑区，看不清一行行是什么字，但标题栏、活动栏、状态栏还是亮的，
所以远处看仍然是「开着编辑器」。变暗程度在阅读设置里调（10%–90%，默认 50%）。

这一栏出现在所有**带外壳的形态**下——VS Code 那两套、飞书文档、企业微信、Word、Excel、PPT
（普通阅读主题里没有内容区可压）。每个形态压的是它自己的「正文那一片」：飞书是文档区、
企业微信是消息区 / 会话区、Word 是那张纸、Excel 是网格、PPT 是幻灯片，
**首页也不例外**（云文档的文档列表、企业微信的会话区、Office 开始屏幕的「最近」）。
开关会记住（`mionovel:dim`）。它和演示模式互不依赖，可以只开一个，也可以一起开：
一份暗着的代码。

### 改快捷键

五条命令的键都能改，在阅读设置的「快捷键」一栏里点一下键位、接着按你想用的组合就行。
`Esc` 取消，`Backspace` 恢复默认，两条命令不能绑成同一个；改完菜单里的提示跟着变。

| 命令 | 默认 | 在哪儿生效 |
|---|---|---|
| 阅读设置 | `S` | 书架、五套办公首页、阅读器 |
| 目录 / 侧栏 | `T` | 阅读器（普通主题的目录抽屉、编辑器形态的侧栏）、编辑器书架 |
| 全屏 | `F` | 书架、五套办公首页、阅读器 |
| 演示模式 | `Alt+Q` | 只属于编辑器形态（VS Code 那两套） |
| 摸鱼模式 | `Alt+S` | 带外壳的形态（VS Code、飞书、企业微信、Word、Excel、PPT） |

带修饰键的那些不管焦点在哪都会响；`S` / `T` / `F` 是单键，所以在输入框里打字时它们让位——
在书架的搜索框里打「s」不会把设置面板敲出来。

## 办公外壳主题

主题列表里另有十套是「让屏幕上是那个软件」的：**飞书 亮 / 暗**、**企业微信 亮 / 暗**、
**Word 亮 / 暗**、**Excel 亮 / 暗**、**PPT 亮 / 暗**。和 VS Code 那两套同一个路子——
选中之后整个应用变成那副样子，不是只换配色。

映射是固定的，每一套都把「书」当成那个软件里的一个文件：

| 主题 | 书架（首页） | 一本书 | 一章 | 换章的地方 |
|---|---|---|---|---|
| 飞书 | 云文档首页（新建 / 上传卡片、最近访问 / 归我所有、筛选与列设置） | 一篇云文档 | 文档里的大标题 | 左侧「大纲」 |
| 企业微信 | 会话列表（还有通讯录 / 日程 / 微盘） | 一个会话 | 聊天记录里的一段 | 右侧「聊天记录」 |
| Word | 开始屏幕（新建 + 最近） | 一份 `.docx` | 一页 | 左侧「导航」窗格 |
| Excel | 开始屏幕 | 一个 `.xlsx` | 一张工作表 | 底部的工作表标签 |
| PPT | 开始屏幕 | 一份 `.pptx` | 一节 | 左侧的节与幻灯片缩略图 |

打开时都是各自的首页，不会自动翻进某本小说。点一下文件 / 会话 / 文档就进阅读器——
正文按那个软件的版式排：飞书是白底上一列字，企业微信是一串消息气泡（一段一条，
发信人写在气泡左上角、取书里的作者名；**双语书的原文段靠右显示成「我发的消息」**，
方便和译文对照），Word 是灰蓝桌面上一张 A4 纸（1px 纸边、四角裁剪标记、功能区和纸之间
11px；标尺在「视图」页签里，打开时两个边距标记落在正文边界上），
Excel 是网格（行号 + A 列正文 + 字数 + 类型，编辑栏跟着当前行走），
PPT 是幻灯片浏览（一张张贴着排，左侧缩略图、下方备注）。

几件所有外壳都守着的规矩：

- **会响的按钮都是真能用的。** Word 的功能区里，复制、字体、字号（增大 / 缩小 / 直接选）、
  行距（下拉选档）、缩进、两种对齐、导航窗格、标尺、阅读视图、全屏、摸鱼模式按下去屏幕真的会变，
  标题栏那个「搜索」框和编辑组里的「查找」是**真的在本章里找**（命中处标出来、算得出第几处、
  回车走到下一处，见 `lib/find.ts`），功能区右下角那个小三角真能把功能区收起来——因为它们
  恰好都是这个阅读器本来就有的设置。Excel 的「冻结首行」、PPT 的「备注」、企业微信功能栏上的
  通讯录 / 日程 / 微盘也都是真的（换的是左边那一栏列什么）。
- **灰着的按钮是真灰的。** 只读文档里本来就该灰的那些命令（粘贴、剪切、格式刷、字体颜色、
  加粗、居中 / 右对齐、替换、选择、批注、评论、纸张上的三个加载项……）一律 `disabled`，
  不装成能用；Word 那一屏的样式库干脆不是按钮——它是文档样式的预览，画成按钮就得能按。
  飞书首页上那三张卡片的「模板库」、
  左边那三项（云盘 / 知识库 / 智能纪要）、底部那三个（打印 / 工具箱 / 回收站）也一样：
  这个应用里没有对应的东西，就灰着，鼠标放上去会说明原因；「与我共享」「收藏」两个页签
  老实空着——本地文件不上传，也没有收藏这个功能，它们各给一句说明，而不是把同一批书
  换个标题再列一遍。
- **不编造数据。** 会话列表里的时间是这本书真实的最近阅读时间，头像字是书里作者的首字，
  未读角标是还没读的章数，工作表的「字数」「类型」两列是数出来的。没有假同事、假用户名、
  假时间戳。
- **图怎么放，每个形态不一样。** 真图只出现在两个地方：**普通阅读器**（几套日间 / 夜间
  主题那一档，安静看一本书时插图该在）和 **PPT 的幻灯片**（一页一张图本来就是它存在的
  意义）；**编辑器（VS Code）、飞书文档、企业微信、Excel 和 Word 都不显示图**——
  那里写的是一行 `![](./OEBPS/Images/pic.png)`，路径是书里的原图地址。
  这条规矩只在一处定义（`lib/blocks.ts` 的 `mediaModeFor`），`verify:apps` 直接
  断言那张表：改哪个形态都跑不掉。
- **演示模式（Alt+Q）仍然只属于 VS Code 那两套**：它生成的是源代码，在 Word 里没有意义。
  摸鱼模式（Alt+S）则五套外壳都有效——它压的是正文那一片。

飞书那一屏（云文档首页）是按真飞书的「主页」一比一复刻的：左边 300px 的空间栏、
  三张动作卡片、四个页签、一张五列的文档列表，连行高（56）、列宽（224）和那个
  排序箭头的位置都是从截图上一像素一像素量出来的。真的能用的：新建 / 上传（导入本地文件）、
  搜索、四个页签、筛选（在读 / 未读 / 已读完）、显示设置（勾选显示的列）、
  列表 / 网格视图切换、头像菜单（阅读设置 / 导入 / 全屏）、行尾的 ⋯（解析设置与删除）。
  配色全部走主题变量，只有飞书的商标和那三张卡片上的彩色插图写死了色号——
  它们是产品插图，跟着主题变色就不像那个产品了。

Word 那一屏也是按桌面版截图一比一复刻的（三张截图：开始屏幕、功能区、视图页签 + 导航窗格）：

- **开始屏幕**（也就是这一套的书架）：左边一条 96px 的导航栏（开始 / 新建 / 打开 … 账户 /
  选项），右边是「新建」三张卡 + 页签行（最近 / 收藏夹 / 与我共享 + 搜索框）+ 一份
  两列列表（名称 / 已修改日期，行高 70）。真的能用的：「空白文档」那张卡 = 导入本地
  txt / epub、搜索框真的能搜（书名 / 作者 / 文件名）、三个页签真的能切、每一行的 ⋯ 是
  解析设置与删除、左栏「选项」= 阅读设置、「打开」= 打开最近读的那一本。灰着的：
  解锁高级模板 / 书法字帖 / 更多模板 / 更多文档 / 账户 / 行尾的图钉与星（本地书架
  没有置顶也没有收藏——所以「收藏夹」那一栏老实空着，不把同一批书换个标题再列一遍）。
- **阅读器**：标题栏（Word 商标 + 自动保存 + 快速访问工具栏 + 居中 370px 的搜索框）、
  十一页页签（右端是批注 / 编辑 / 共享）、一行行格子的功能区（剪贴板 / 字体 /
  OfficePLUS / 段落 / 样式 / 编辑 / 论文助手 / 加载项 / PDF工具箱）、灰蓝桌面上一张
  794×1123 的纸（四角裁剪标记）、状态栏右边的专注 / 视图 / 缩放。
- **视图页签**照截图摆四组：文档视图（单独的页面 / 阅读视图 / 沉浸式阅读器）、缩放
  （缩放下拉 + 回到 100%）、显示（标尺 / 导航 / 页眉和页脚 / 脚注 / 尾注）、深色模式
  （在 Word 亮 / 暗之间切）。灰的是页眉和页脚、脚注、尾注——书里没有这三样。
- **导航窗格**：一行「← 导航」（那箭头真能收起来）+ 三页（标题 / 查找 / 替换）+ 一个
  「在文档中搜索」的框 + 内容区。那个框和标题栏正中间那个是同一个章内查找（在哪儿打字
  都在正文里标出来，计数也一样）；「替换」灰着——只读文档改不了字。

尺寸与颜色都是从截图上量的，四个纸与控件专用的值（纸边、裁剪标记、控件描边、搜索框底色）
进了主题注册表的 `page` 那一层（`--mn-page-*`），组件里一个色号都没有。「自动保存」停在
「关」（本地文件不上云），「升级计划」那个牌子上**没有那颗红点**——那是「有未读通知」的
意思，我们没有这件事。

Excel 那一屏同样是按桌面版的两张截图一比一复刻的（开始屏幕 + 工作簿窗口）：

- **开始屏幕**：标题栏右端一片淡灰的商标水印，左边一条 96px 的导航栏（开始 / 新建 /
  打开 … 账户 / 选项），右边一句**按钟点换的问候**（「下午好」，读的是这台设备现在的
  时间）、一颗绿色的「新建空白工作簿」、三个药丸（最近 / 收藏夹 / 与我共享）、右边一个
  「搜索文件」框、右下角「更多工作簿 →」，中间是文件列表（名称 / 修改时间 / 类型 / 大小）。
  真的能用的：绿按钮 = 导入本地 txt / epub（拖进来也行）、搜索框真的能搜（书名 / 作者 /
  文件名）、三个页签真的能切、行尾的 ⋯ 是解析设置与删除、左栏「选项」= 阅读设置、
  「打开」= 打开最近读的那一本。灰着的：左边那个「>」方框（真 Excel 里是使用向导）、
  账户、更多工作簿；「收藏夹」「与我共享」两栏老实空着。
- **阅读器**：标题栏（Excel 商标 + 自动保存 + 快速访问工具栏 + 居中 368px 的搜索框 +
  升级计划）、十二页页签（右端是批注与共享）、**十一组格子**的功能区（剪贴板 / 字体 /
  对齐方式 / 数字 / OfficePLUS / 样式 / 单元格 / 编辑 / 便捷工具 / 加载项 / OfficePLUS）、
  编辑栏（名称框 + ✕ ✓ fx + 编辑栏本体 + 展开记号）、网格（A/B/C 列标题 + 行号 + 绿框
  圈住的当前行 + 右下角那个填充柄）、底部的工作表标签条（白底 + 上圆角 + 一条绿线的当前
  工作表、＋、列出全部工作表的 ⋮）、状态栏。
- **视图页签**四组：工作簿视图（普通 / 页面布局 / 分页预览 / 自定义视图）、显示
  （网格线 / 编辑栏 / 标题 / 标签 / 冻结窗格——五个都是真开关）、显示比例（缩放下拉 /
  100%）、窗口（全屏 / 摸鱼模式）。灰的是页面布局、分页预览、自定义视图。
- 网格里那三件真东西：**编辑栏与名称框跟着视口走**（写的是「现在正看着的那一行」的地址
  与原文）、**工作表标签就是章**（点标签换章、‹ › 翻上下一张、⋮ 列出全部）、
  **当前行是绿框**。短章的下面还会补一片**空格子**（只有行号与网格线）——Excel 里往下一路
  都是格子，不是一片白。

尺寸与颜色也是从截图上量的（1917×1006 与 1920×1079 两张），网格那一层的值进了主题注册表的
`sheet` 那一层（`--mn-sheet-*`）：网格线 `#E0E0E0`、行列标题底 `#F0F0F0`、标题行的底线
`#ABABAB`、当前行列标题垫的 `#E1E1E1`、**选中框的绿是 `#217346`**（Excel 从 2007 用到今天
的选中绿，和品牌绿 `#107C41` 是两个色，同一张截图里同时出现）、标题栏 / 页签行 /
工作表标签条 / 开始屏幕左栏共用的那层 `#E4EAEE`、控件描边 `#8A8A8A`。组件里一个色号都没有。

阅读模式（上下滚动 / 左右翻页）在这些外壳里不适用：它们的版面不是你自己的排版，
是那个软件的（纸张、网格、幻灯片、消息流），所以这些主题下设置里会写明这一点，
切回普通主题就能用分栏翻页。

选中任何一套时都会顺带把阅读设置调成它自带的那一套（Word 是宋体 16px、首行缩进两字符，
Excel 是小一号的字，企业微信是聊天那种行距），之后就完全按你自己的设置走。

颜色是抄的，不是调的：Word / Excel / PPT 的中性色取自 Fluent 2 的官方 token 表
（Office 桌面版与网页版共用这一套），品牌色是 Office 三件套的官方色（Word `#185ABD`、
Excel `#107C41`、PowerPoint `#C43E1C`）；飞书是 `#3370FF` 加中性色 `#1F2329` / `#646A73` /
`#8F959E` / `#F5F6F7`；企业微信照桌面版截图量出来（淡蓝功能栏 `#DBE9F7`、气泡 `#E4E7EB`、
会话底 `#F5F7FA`、选中态 `#267EF0`／`#3586F4`）。
配套约束与踩过的坑见 [docs/SPEC.md](docs/SPEC.md) 五 5.5 与决定记录 26–31。

## 几个不能随便改的地方

- **主题只能通过注册表加**。往 `themes/builtin.ts` 里加一条数据就行；不要在组件里写死颜色，
  也不要在 CSS 里为某个主题写选择器。所有颜色都是 `:root[data-theme=…]` 上的变量，
  组件只认 `bg-bg` / `text-fg-muted` 这类工具类。破了这条，换主题就会只换一半。
- **界面形态也由主题声明，组件不许认主题 id**。`chrome` 是六种形态之一：
  `plain`（默认阅读器）、`code`（VS Code）、`doc`（飞书文档）、`chat`（企业微信）、
  `page`（Word）、`sheet`（Excel）、`slide`（PPT）。组件读 `useChrome()` / `chromeOf()`，
  样式只挂在各自的根类上（`.mn-code` / `.mn-doc` / `.mn-chat` / `.mn-office--*`）。
  要判断「这是哪种形态」，永远看这个标志，不要写 `themeId === 'vscode'`——
  那样再加一套同形态的主题就得改一遍组件。
- **正文怎么切块只有一处**（`lib/blocks.ts`）。编辑器的一行、表格的一行、聊天的一条、
  幻灯片的一张，切法完全一样：「最里层的块级元素，外加把 figure 拆开、给落单的图包一层」。
  加一种新形态时从这里起步，别再写一套遍历——同一个形态里切出不同的段数，四个地方会各说各话。
  各形态只决定「怎么摆放、怎么上色」（`lib/chat.ts` / `lib/sheet.ts` / `lib/slide.ts` 是纯函数，
  外壳和正文各算一遍也对得上）。
- **编辑器形态下的正文只贴标签、不写字**。`lib/code.ts` 给段落贴 `mn-tok-*` / `mn-code-line`，
  颜色在 `styles/code.css` 里从 `--mn-code-*` 取。别往正文里插原文没有的记号（`//`、`def` 之类），
  也别在 JS 里写死颜色。唯一的例外是图片：它写成一行 `![](./原图路径)`——图不渲染，
  那行就是「这里有一张图」。分好的类名要能被 `content.css` 的排版规则继续管着
  （一套排版管两种形态）。
- **演示模式的名字必须同源**。`lib/decoy.ts` 里文件名和文件里的类名都从同一个 `Ctx`
  （`makeCtx(preset, seed)`）推出来，而 `seed` 由 `decoySeed(bookId, chapterIndex)` 统一给出——
  目录树、标签页、正文三处必须传同一个。各自哈希一遍的后果是 `ReportMapper.java` 里写着
  `class CatalogService`，那是懂代码的人一眼就看得出的假。加语言时照这个约定加：文件名的推法、
  文件头（`preamble` / `open` / `fields` 都是「组」，要么整段写进去、要么整段不写）、
  块、收尾、单行填充，然后跑 `bun run verify:decoy`。
- **演示模式生成的是纯文本，不是带颜色的 HTML**。上色统一交给 highlight.js
  （`lib/highlight.ts`，按行 tokenize，颜色映射见 `styles/code.css` 的 `.hljs-*` 一段）。
  别在模板里手写颜色——自己写一套 token 规则既不准也维护不动。
- **代码的缩进靠 `white-space: pre-wrap`**（`.mn-content--code`）。HTML 默认把行首空白折掉，
  少了那一条，生成得再对也会平铺到左边——一眼假。这条和上面那条是一对，改一个要看另一个。
- **动效只用 `--mn-dur-*` 和 `mn-*` 那几个工具类**（见 `styles/app.css`），不要在组件里现编毫秒数或
  新写一套 keyframes。新加一种「出场感」之前先看现有的四条能不能复用；所有动画都要能被
  `prefers-reduced-motion` 压掉——那条 `@media` 块不能删。
- **摸鱼模式压暗的是正文区，不是整个窗口**。程度写在根上的 `--mn-dim`，
  正文那一片用 `.mn-veil` 盖一层黑纱（`styles/office.css`）；标题栏、功能区 / 工具条、
  状态栏不压暗。以后再往哪个形态里加正文区，要么让它落在那一片里，要么在那个新块上
  补一条同样的规则——整窗压暗会让它从「暗着的软件」变成「屏幕关了」，那是另一回事。
- **办公外壳里只有会响的按钮才可点**。只读文档里本来就是灰的命令写成 `disabled`
  并给出原因（`title` 里写清「只读」或「这个外壳里没有」），不摆点了没反应的按钮。
  这条比「看起来像」重要：一个按下去没反应的「发送」「格式刷」，比少一个按钮更容易露馅。
- **办公外壳不编造数据**。文件名从书名来（加 `.docx` / `.xlsx` / `.pptx`），
  发信人是书里的作者（没有就写「书友」），时间是真实的最近阅读时间，未读角标是没读完的章数，
  工作表里的字数与类型是数出来 / 分类出来的。唯一的例外是各软件自己的结构性标签
  （行号、页数、幻灯片序号、`Ln 171, Col 26`），它们说的是「这是第几段 / 第几页」，
  不是编出来的内容。
- **全局快捷键只有一处监听**（`hooks/useGlobalHotkeys.ts`），判定在 `lib/hotkey.ts`。
  加功能不要自己再挂一个 window 监听；判定按 `event.code`（物理键位）而不是 `event.key`——
  Alt 组合下 `key` 会跟着键盘布局变。录键期间 store 里的 `recording` 标记会让全局监听整个让位，
  录键控件自己也要吃掉那一下按键（capture + preventDefault + `data-mn-esc-local`）：
  少了这两条，用户想把 Alt+S 绑给别的功能时，摸鱼模式会先被切一遍。
- **翻页模式下别给 `.mn-content` 加位移/缩放动画**。`transform` 是翻页的地盘（translateX 表示当前页），
  两条动画抢同一个属性会让翻页一顿一顿的——所以换章的淡入在翻页模式只动 `opacity`。
- **`parsers/epub/html.ts` 里的 `scrubDocument()` 不能删**，也别把安全性完全交给 DOMPurify。
  实测 DOMPurify 在某些 DOM 实现下（比如 happy-dom）会静默什么都不做——连 `<script>` 都不删。
  我们用 `innerHTML` 注入正文，所以危险标签和 `on*` 属性必须由自己那层删掉。
- **解析器不要直接碰 Dexie**，一切通过 `ParseSink` 交出去。这是「30MB 的 txt 峰值内存只有单章」
  的前提：一旦解析器自己把全书留在数组里，大文件就会把标签页撑爆。
- **别用 localStorage 存书或章节**。localStorage 只能放字符串且有 5MB 上限，
  书和章节一律进 IndexedDB；localStorage 只有阅读设置（几百字节）在用。
- **进度只存「章序号 + 章内比例」**，不要引入 CFI 之类的格式专属定位。
  现在滚动和翻页、txt 和 epub 共用同一套进度模型，所以切换阅读模式或重新解析都不会让进度错位。
- **正文不要塞进 iframe**。iframe 里拿不到外层的 CSS 变量，主题要么注入第二份、要么维护两套——
  koodo-reader 就是那样，加一个可主题化的界面就要改两个仓库。我们用净化 + 作用域 CSS 拿到隔离。
- **`ReaderView.tsx` 里翻页模式的测量不能去掉失败保护**。容器宽度还没就位时量出来的页宽会把正文挤成一条窄柱，
  页数暴涨，而且因为没有尺寸变化，`ResizeObserver` 之后不会来纠正——必须重试到量成功为止。
- **翻页模式的 `.mn-frame--paged` 一屏裁剪窗口不能拆**。桌面宽窗口下正文栏宽远小于视口，
  没有它 translateX 之后上一页和下一页会同时露在两侧；宽度和中缝必须是整数，多列布局的可见列数是
  `floor((容器宽 + 中缝) ÷ (列宽 + 中缝))`，差一个像素就少算一列。整页插图也依赖 `--mn-page-height`
  限高 + 翻页模式下去掉垂直边距，否则图会被挤去下一列，当前页变成空白页。
- **滚动模式进章时的位置恢复，只在版面变了的时候重写 `scrollTop`，读者一动手就停**。
  重写同一个位置没有别的作用，只会把读者刚滚走的位置拽回来——症状是「章首往下滚突然回弹、
  章末往上滚被拽回章末」。
- **`bun run verify` 必须过**。它覆盖的是最容易悄悄坏掉的部分：编码识别、分章、目录归并、
  图片路径重写、净化、锚点落点。没有 CI，这个脚本就是回归防线。
- **锚点 id 必须带 `mn-` 前缀**（解析时统一加，链接侧同前缀重写）。不加的话真实浏览器里
  DOMPurify 会按 DOM clobbering 把 `id="target"`、`id="name"` 这类删掉，脚注就跳不到位置了；
  happy-dom 下它是空转的，验收脚本看不出来，所以这条只能靠约定守住。
- **界面文案只写具体事实**（见 [AGENTS.md](AGENTS.md)）：不写「点一下就能……」这类旁白、
  不写「全是本地文件，不上传」这类自我说明、不罗列功能、不写 changelog。`verify:apps`
  里有一条黑名单断言盯着这个（删过的那几句不许回来）。
- **别复用一个语义不同的类名**。`.mn-doc__tool` 既当过首页的筛选触发器、又是阅读器工具条
  那一格，结果首页按钮被工具条的固定尺寸压扁、字溢出到邻居身上。
